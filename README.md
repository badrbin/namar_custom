# Demo — تجربة نقل حساب التخصيم

تطبيق مستقل لموقع التجربة `testnamar.u.frappe.cloud`، متوافق مع Frappe 15.
ينقل واجهة «حساب التخصيم» ومحرك `get_cutting_values_bulk_exclusions_test` إلى ملفات التطبيق، مع المحافظة على نتائج الحساب الحالية.

التثبيت وحده لا يفعّل الواجهة الجديدة ولا يعطّل السكربتات السابقة. يبدأ التطبيق غير مفعّل، وتتاح مقارنة الحساب الجديد لمستخدم System Manager. بعد المقارنة، تستبدل عملية التفعيل الذرية الواجهة والحساب السابقين، مع إبقاء السجلين محفوظين ومعطّلين للرجوع.

لا ينقل التطبيق واجهات تسجيل التصنيع أو إنشاء القيود أو إدارة الحزم. يحتفظ باستدعاءاتها الحالية.

## التحقق المحلي

```bash
python -m unittest discover -s tests -p 'test_*.py'
node tests/test_frontend.js
```

## التفعيل والرجوع على التجريبي

- قراءة الحالة: `demo.api.migration_status`.
- مقارنة الحساب: `demo.api.calculate_cutting`؛ نفس مدخلات وعقد الحساب السابق.
- التفعيل: POST إلى `demo.api.activate` بعد اجتياز المقارنة والاختبار.
- الرجوع: POST إلى `demo.api.deactivate` بعد مراجعة الحالة. يعيد تفعيل السجلين القديمين دون حذف البيانات.
- تتطلب عمليتا التبديل دور System Manager، والموقع المحدد، وتطابق بصمتي السكربتين مع نسخة النقل. لا تنفّذ تغييرات في الإنتاج.
- واجهة API القديمة تبقى متاحة: تستدعي Server Script السابق قبل التفعيل، ومحرك Python الجديد بعده.
- أعد تحميل النموذج بعد التبديل؛ الصفحات المفتوحة سابقًا قد تحتوي واجهة محملة قبل التفعيل.

لا تُنفذ إعادة محاولة تلقائية للنشر أو التفعيل. بعد انقطاع الطلب اقرأ الحالة أولًا.
